## 二、精選 AI 協作深度案例紀錄（3 筆）

### 【案例一】策略因子 Point-in-Time（嚴防偷看未來）演算法設計

* **協作角色**：組員 C（徐靖洋）

* **問題情境**：在量化回測中，最致命的偏誤是「前視偏誤（Lookahead Bias）」。若月度因子標準化跨月計算，或取用了訊號日次日的資訊，會產生虛假的超額報酬。

* **Prompt 輸入**：

  > 「在計算台股每月底的因子分數時，我們需要標準化（z-score 與百分位排名）。請提供一段 pandas 程式碼與對應的 pytest 測試，證明我的計算完全沒有前視偏誤（不能用到任何訊號日之後的資料），並確保除權息日不會造成回撤指標失真。」

* **AI 產出建議**：

  1. 回撤計算改用 `(1.0 + ret_pct.fillna(0.0) / 100.0).cumprod()` 連乘生成總報酬指數（Total Return Index, TRI），解決除息日收盤價暴跌造成的「偽回撤」。

  2. 標準化函數 `standardize()` 限定在 `groupby("signal_date")` 單一月份橫截面內進行，禁止跨期計算。

  3. 提供 `test_no_lookahead` 單元測試：將訊號日 $T$ 之後的市場資料全數截斷切除，比對完整資料集與截斷資料集在 $T$ 日的因子值與 z-score，數值差異小於 $10^{-15}$。

* **應用成果**：成功整合至 `src/build_factors.py`，並成為組內程式碼審查（Code Review）必過的防呆單元測試。

* **Prompt 輸入**：

  > 「請為我們構建回測引擎的持倉撮合邏輯。每期初總資產分成 10 等份，每檔分配目標資金。請計算每檔以收盤價能買進的最大整張股數（1,000股倍數），並將買進金額、手續費（0.1425%）、滑價（0.05%）精確扣除，剩餘金額留作現金。調倉日賣出舊部位時，需扣除手續費、證券交易稅（0.3%）與賣出滑價。請寫出向量化或高效率的資料結構。」

## 三、真實除錯與修復紀錄（實際發生的錯誤與修正）

本組在執行測試過程中，曾遭遇兩項真實發生的重大錯誤，並透過與 AI 協同除錯完成修復：

### 🚨 錯誤一：Python 浮點數精度導致交易手續費計算偏差與測試斷言失敗

* **發生情境**：
  組員 E 執行 `behave features/quant_rules.feature` 時，第六個 Scenario 出現斷言失敗：

  ```
  Scenario: 賣出股票時必須扣除手續費與證券交易稅
    Given 帳戶持有每股 100 元買入的 "2330" 共 1000 股
    And 券商手續費率為 0.1425%，證券交易稅率為 0.3%
    When 以每股 120 元全數賣出
    Then 帳戶實際入帳金額必須為 119469 元
  
  ```

  **報錯訊息**：
  `AssertionError: Expected 119469, but got 119470`（短少扣除 1 元手續費！）。

* **根本原因分析（Root Cause）**：
  在原始程式碼中，組員使用 `math.floor(trade_value * self.fee_rate)` 計算手續費：

  * 成交金額：$120 \times 1,000 = 120,000$ 元。

  * 手續費理論值：$120,000 \times 0.001425 = 171.0$ 元。

  * 然而在 IEEE 754 浮點數運算中：
    `120000 * 0.001425` 在 Python 內部的實際暫存值為 `170.99999999999997`！

  * 當直接呼叫 `math.floor()` 時，`170.99999999999997` 被無條件捨去為 **`170`** 元！

  * 導致入帳金額計算為 $120,000 - 170 - 360 = 119,470$ 元，產生了 1 元的計費差錯。

* **AI 協同除錯與修復方案**：
  將問題代碼提供給 AI 分析後，AI 建議在取整前加入精度微調，或使用 `round()` 截斷浮點誤差：

  ```
  # 修正前：
  fee = max(self.min_fee, math.floor(trade_value * self.fee_rate))
  
  # 修正後（加入 round 消除 170.99999999999997 浮點誤差）：
  fee = max(self.min_fee, math.floor(round(trade_value * self.fee_rate, 4)))
  tax = math.floor(round(trade_value * self.tax_rate, 4))
  
  ```

* **修復驗證**：
  修復後重新執行 `behave`，手續費正確計算為 171 元，入帳金額精準等於 119,469 元，測試全數 PASS（詳見 `螢幕擷取畫面 2026-11-08 012328.png`）。

### 🚨 錯誤二：自訂例外類別型態不一致導致品質檢查中斷

* **發生情境**：
  在 Scenario 4 中，規則要求股票連續停牌缺值 3 天以上時，系統必須拋出專屬異常 `DataMissingAnomaly`：

  ```
  Then 系統應拋出 "DataMissingAnomaly" 例外並將該標的排除於當日選股清單
  
  ```

  在初版 steps 中，`check_continuity` 拋出的是泛用的 `ValueError`，導致：
  `AssertionError: 預期 DataMissingAnomaly，但收到 ValueError`。

* **修復方案**：
  與 AI 討論後，在 `quant_rules_steps.py` 最上方顯式宣告領域例外：

  ```
  class DataMissingAnomaly(Exception):
      """資料品質檢驗連續缺失專屬異常類別"""
      pass
  
  ```

  並在檢查函式中精確拋出 `DataMissingAnomaly`，使業務領域語言（Ubiquitous Language）與自動化測試完美吻合。
